# busy-metrics

`crates/metrics` — `sources()` returns CPU, Memory, Disk, Network, Battery, Processes. Files: `cpu.rs`, `memory.rs`, `disk.rs`, `network.rs` (+ `wifi.rs`), `battery.rs`, `processes.rs`, `util.rs`; PDH goes through `busy_win::pdh`.

Live check: `cargo run -p busy-metrics --example dump_metrics [samples]`.

## Per source

| Source | API | Notes |
|---|---|---|
| CPU | PDH `\Processor Information(*)\% Processor Utility`, `% Privileged Utility`, `% Processor Performance` (English counters) | Utility exceeds 100 under turbo → total clamped; user/kernel split uses the *uncapped* privileged/total ratio (capping made user read 0). Freq = `% Processor Performance` × registry `~MHz` (fallback `CallNtPowerInformation`). Fallback path: `NtQuerySystemInformation(SystemProcessorPerformanceInformation)` (only the calling thread's processor group). |
| Memory | `GlobalMemoryStatusEx`, `GetPerformanceInfo`, `NtQuerySystemInformation(SystemMemoryListInformation)` (class 80) | `cached` = `SystemCache` × page size — lower than Task Manager's standby+modified. Page lists: modified = `ModifiedPageCount`, standby = Σ `PageCountByPriority[0..8]`, free = free + zero; hand-defined struct (phnt) with size assert. Works unelevated (Win11 26200). Matches PDH `\Memory\Modified Page List Bytes`, Σ `Standby Cache {Reserve,Normal Priority,Core} Bytes`, `Free & Zero Page List Bytes` within sampling skew; standby + free == `ullAvailPhys`. Pools = `KernelPaged`/`KernelNonpaged` × page size (match PDH `Pool Paged/Nonpaged Bytes`). Hardware reserved = `GetPhysicallyInstalledSystemMemory` (read once, SMBIOS) − `ullTotalPhys`; `None` when SMBIOS reports less than visible RAM (some VMs). `compressed` = store working set from `NtQuerySystemInformation(SystemStoreInformation)` (class 109, `MemCompressionInfoRequest` 22, request v3; v1/v2 fail with `STATUS_INVALID_PARAMETER` on 26200), ~10 µs, unelevated; equals `(Get-Process 'Memory Compression').WorkingSet64`, which `OpenProcess` can't read unelevated (access denied). |
| Disk | PDH `\PhysicalDisk(*)` read/write bytes/s, `% Idle Time`, `Avg. Disk sec/Transfer` | active = 100 − idle. Query rebuilt ≤ every 10 s on failure. Volumes (fixed drives) refreshed every 10 s. Read/written totals: `Counter::each_raw` (`PdhGetRawCounterArrayW`) on the bytes/s counters — a PERF_COUNTER_BULK_COUNT's raw `FirstValue` is the byte count since boot — minus the value when the disk number was first seen (rebased if it goes backwards). Verified within 0.05 % of Σ rate × Δt over 10 samples. Volume → disk: drive letters in the instance names ("2 C: H:"), re-applied on every successful read (letters can move); spanned volumes take the lowest disk number; matches `Get-Partition`. No volume handle is opened (`IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS` would need one per volume). `is_system` = drive of `GetSystemWindowsDirectoryW`, read once. |
| Network | `GetIfTable2` for discovery (every 60 s or on IPv4 change), `GetIfEntry2` per sample, `GetUnicastIpAddressTable` every 10 s | `GetAdaptersAddresses` was 6–9 ms — don't reintroduce it on the hot path. `kind`: `IF_TYPE_IEEE80211` → Wifi; `IF_TYPE_ETHERNET_CSMACD` + `HardwareInterface` → Ethernet (vEthernet/TAP report type 6 too); else Other. Wi-Fi (`wifi.rs`): wlanapi.dll loaded at runtime through `busy_win::Dll` (System32; absent on some Server installs, where an import would stop the app from starting); `WlanOpenHandle` fails while WLAN AutoConfig is stopped → `None`, retried every 60 s. The client handle is opened once and kept; an error other than not-associated drops it (service restart) and it is reopened after 60 s. `WlanQueryInterface(current_connection)` (~16 ms!) + `WlanGetNetworkBssList` for the channel (~13 ms, cached scan list, no new scan; entry count checked against the list size and capped at 1024) run when a Wi-Fi interface connects and every 60 s; `wlan_intf_opcode_rssi` (~0.2 ms) every 5 s. Interface GUID = `MIB_IF_ROW2.InterfaceGuid`. `signal_pct` equals netsh "Signal"; not a linear function of RSSI (74 % at −48 dBm). Checked vs `netsh wlan show interfaces` (SSID, signal 88 %, RSSI −49 dBm, channel 52 = 5260 MHz). |
| Battery | `GetSystemPowerStatus`; SetupDi + `IOCTL_BATTERY_*` for rate/capacity/cycles | Capacity refreshed every 60 s. Devices opened `GENERIC_READ` only: the three query IOCTLs encode `FILE_READ_ACCESS` (only `IOCTL_BATTERY_SET_INFORMATION` needs write). **Untested on real battery hardware** (dev machine is a desktop). |
| Processes | one `NtQuerySystemInformation(SystemProcessInformation)` into a reused buffer | Hand-defined `SYSTEM_PROCESS_INFORMATION` with compile-time size/offset asserts (x64). Deltas keyed by (pid, CreateTime). CPU% normalized to all logical CPUs. "Memory Compression" excluded from `by_mem`. |

## Network counting rule (totals)

Count an interface if: connected, not loopback, not a filter/LWF row, `HardwareInterface` set. Excludes vEthernet/vSwitch/VPN/tunnels whose traffic also crosses a physical NIC. If no hardware interface is connected, sum all connected non-filter non-loopback ones.

## Measured cost (release, i9-10900KF, ~310 processes)

CPU 0.6–5 ms · Memory <0.3 ms · Disk 0.15–0.3 ms (incl. response time + raw totals) · Network ~0.3–0.5 ms (+~30 ms once a minute while Wi-Fi is connected) · Battery µs · Processes 4–13 ms (scales with thread count). `sources()` construction 0.4–0.8 s (first PDH query).

## Gotchas

- First sample: Processes/Network rates are 0; CPU/Disk collect once in the constructor so they have data.
- PDH instance churn (hot-plugged disks, cores) must be tolerated — re-parse instance names each sample. Disk keeps its list as a field and matches entries by instance name each sample, so churn only adds or drops entries.
- A formatted PDH value is usable only when its `CStatus` is `PDH_CSTATUS_VALID_DATA` (0) or `PDH_CSTATUS_NEW_DATA` (1); any other status (e.g. `PDH_CALC_NEGATIVE_VALUE` on a rate counter whose instance just restarted) carries garbage and is skipped. `busy_win::pdh` applies this to every read.
- PDH instance names are decoded with `WideCharToMultiByte` into one buffer reused for every instance (`ArrayBuf`), then passed on as `&str`. Rust's own UTF-16 decoders (`from_utf16_lossy`, `char::decode_utf16`) are instantiated in our crate, so in debug builds they made the GPU source (~600 `GPU Engine` instances here) 1.5–4 ms a tick slower; `String::from_utf16` is fast but allocates a `String` per instance.
